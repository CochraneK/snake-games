# 贪吃蛇合集 · Snake Games

同一个开放世界贪吃蛇**引擎**，多个「蛇」版本。当前内置：

- **苏络**（`?theme=su`）：蛇身是「苏络苏络…」文字链，吃「苏」「络」发光豆子
- **77**（`?theme=77`）：蛇身是「7777…」数字链（旧链接 `?theme=cc` 仍可用，自动指向 77）
- **北京地铁**（`?theme=beijing`）：**线路可换乘的地铁收集玩法**，**28 条线全部出战**
- **南京地铁**（`?theme=nanjing`）：同上，**16 条线**

大地图、相机跟随、多蛇抢食，**两种死亡规则可切换**。地铁版与文字版在代码里是两个独立模块（`MODES`），引擎不判断模式。

## 玩法（地铁版）：线路可换乘 + 全网点亮获胜

这是地铁版的核心玩法，三条规则：

1. **开局随机分配线路** —— 每条蛇（包括玩家）随机领到一条线，每条线恰好一条蛇；
2. **换乘站可以切换线路** —— 吃到经过 ≥2 条线的车站时，可以跳到另一条线：
   蛇的**名字和颜色立刻跟着换**（你从「1号线」变成「6号线」），每条线的建设进度**分别保留**，
   换回来时接着建。AI 也会换乘，它倾向于换到「自己还没读多少站」的弱线；
3. **全网点亮即通关** —— HUD 的「全网 X / 410」是本局目标：
   把全网所有车站的卡片都读过一遍就算通关（北京 410 站 / 南京 266 站）。

换乘面板长这样（吃到三线枢纽「苹果园」时）：

> **在 苹果园 换乘到哪条线？**　[■ 1号线] [■ 6号线] [■ S1线]　`不换，继续走本线`

于是热门换乘站（111 个）自然成了争夺焦点 —— 「往哪条线跳」成了真正的策略。

## 机制③：成就大图（全城线路图，点亮 = 打过卡）

toolbar 的「🏆 成就图」把当前城市**所有线路的站点一次画成一张图**（北京 410 站 / 南京 266 站）：

| 站点状态 | 样子 | 含义 |
|---|---|---|
| 还没去过 | 淡灰小点 | 没吃过 |
| 吃过、还没读卡 | 白心圈 | 吃过，但还没弹过这站的卡片 |
| **已点亮** | **金色实心 + 光晕** | **吃过，并且弹出过这站的卡片（= 读过）** |
| 换乘站 | 更大一圈 | 多个线共用 |

- 线路本身画成折线：从「本线第一个已点亮站」到「最后一个已点亮站」的那一段用**线路色**点亮，于是进度像电流一样沿着线路蔓延。
- 两种视图：**本线高亮**（默认，其余线路压成淡灰，28 条线也不糊）/ **全网着色**。
- 点图上任意站点 → 底部显示站名、所属线路、当前状态；标题显示 `已点亮 X / Y 站（%）`、`换乘枢纽已点亮 X/Y`。
- 进度存在 `localStorage`（按城市分开），关掉浏览器再回来还在。
- 链接直达：`play.html?theme=beijing&map=1`

**线路图怎么画出来的？** 项目里**没有任何坐标数据**，靠算法算：
节点 = 唯一站名，边 = 同线相邻站，然后四股力反复迭代 320 轮：

1. **硬分离**：任意两点距离不得小于各自半径之和（换乘站半径更大）—— 保证不重叠、不糊
2. **弹簧**：同线相邻站维持理想间距
3. **角度拉直**：把每条线的折角往直线上收 —— 可读性的关键
4. **交叉消除**：两条线段相交时沿中点连线把它们推开

> 迭代顺序有讲究：**分离必须放在每轮最后**，否则前面几股力留下的重叠清不掉。
> 固定随机种子 → 每次打开都是同一张图。北京约 30ms 算完，只在打开时算一次。

## 机制①：空间秩序（专门解决「所有蛇挤成一团」）

地图 64×64、常驻豆子 170 个、同时最多 28 条蛇。如果按老办法「纯随机放豆子 + AI 朝最近的豆子冲」，
几十条蛇会朝同一片豆子汇聚、互相穿身互撞，最后变成互相掉肉的人堆。四层对策：

| 层 | 做法 | 代码 |
|---|---|---|
| 分区配额 | 地图切成 8×8=64 个分区，每区豆子有上限（`ZONE_CAP=5`），超了就往空区搬 | `pickFoodCell` / `rebalanceFood` |
| 分散选点 | 放蛇和补豆子都取「离所有蛇最远」的格子（采样 `SPREAD_SAMPLES` 次取最优），并避开蛇嘴边 | `pickSpreadCell` |
| 个人空间 | 每拍刷一张分区密度图；AI 选向时对「本格 + 前方 2 格的拥挤度」和「3 格内的别的蛇头」加惩罚 | `buildDensity` / `crowdAt` / `steerScore` |
| 尾随豁免 + 被围豁免 | 允许跟着别人的**尾巴**钻过去（对方这一拍正好腾空）；四面被堵时短暂免罚，不会被围死 | `TAIL_SLACK` / `SQUEEZE_TICKS` |

另外：**蛇头周围太挤时会亮一个脉冲红环**，提示「往空处走」。
所有旋钮都在 `play.html` 顶部（`DN / ZONE_CAP / ZONE_SOFT / SPREAD_SAMPLES / CROWD_W / CROWD_RING / TAIL_SLACK / SQUEEZE_TICKS / FOOD_REBALANCE`），想更松或更挤直接调。

## 机制②：站点打卡卡（同一个站吃到第 N 次弹卡片）

同一个车站（文字版是同一个字）累计吃到第 `CARD_AT=3` 次，就弹一张卡片，
讲这站附近的**景点 / 历史 / 美食 / 换乘**，同时一次性奖励 +2 节。

**弹卡 = 自动暂停游戏**，方便阅读：
- 底部固定一条「⏸ 游戏已暂停，读完再继续」+「继续 ▸」按钮（卡片内容再长，按钮也一直在）；
- 关闭方式：点「继续」/ 右上角 ×/ 点卡片空白处 / 按**空格、回车或 Esc**；
- **不再自动关闭**（内容有 6～7 段，6.5 秒根本读不完）；
- 关闭后恢复到「弹卡前」的暂停状态——如果你本来就是暂停状态看地图，不会被强行开始；
- 每站只弹一次，弹过就进图鉴（toolbar「🗂 站卡图鉴」），不会反复打断你。

卡片内容**分五层数据叠加**，保证任何站都有实质信息，而不是空话：

| 层 | 数据 | 覆盖 | 举例 |
|---|---|---|---|
| A 区位 | `AREA_SEGS` 按线路区间写「第 A 站到第 B 站属于某区」 | **全网 100%**（北京 410 / 南京 266） | 「属大兴」 |
| B 手写精选 | `CARDS[城市][站名]` 手写地标与贴士 | 北京 73 / 南京 28 站 | 「天安门广场、国博、人民英雄纪念碑」 |
| C 片区吃食 | `FOODZONE` 区域 → 代表性吃食（品类级，不虚构店名） | 33 个区域 | 「庞各庄西瓜（季节性）」 |
| D 地标类别 | 从站名关键词自动判（公园/山/寺/高校/机场/城门…） | 全网 | 「山体景区」「铁路门户」 |
| E 历史沿革 | `HISTORY[城市][站名]` 手写这一站的历史来历 | **北京 122 / 南京 76 条** | 「明清皇城南门一带，见证开国大典与国庆阅兵」 |

历史沿革的写法有两条纪律：
- **只写有把握的**：① 地名的由来（桥/寺/宫/门/寺的地名几乎都留有史迹，最可靠）；
  ② 有明确遗存或机构的（纪念馆、博物馆、旧址、园区）。
- **不写编年式的精确年份，不做未经核实的轶闻**。宁可少说一句，也不写错。

所以大钟寺那条是「原名觉生寺，因寺内明代永乐大钟得名；寺旁古钟博物馆收藏永乐大钟」，
而不是「1996 年某日某位皇帝铸造」——后者听着更带劲，但容易错。

再加上**线路数据自动生成**的三块：**站序**（第 N 站 / 全线 M 站 / 起终点）、**邻站与到终点站数**（"往安河桥北方向还有 34 站"）、**可换乘线路**。

所以即使一个站从没手写过（573 站曾是这样的），卡片也是：
> **天宫院**　4号线 · 大兴
> 位置：本线第 35 / 全线 35 站（安河桥北 ⇄ 天宫院）· 属大兴
> 邻站：上一站 生物医药基地、本线终点站
> 这片区吃：大兴新城的面食与家常菜、庞各庄西瓜（季节性）、机场周边的连锁餐饮
> 往 安河桥北 方向还有 34 站；本线终点站

⚠ 两个容易踩的坑，都已修：
- **两城重名站会串卡**（新街口 / 杨庄 / 奥体中心）—— 所以 `CARDS` 按城市 id 分组，查卡必须走 `cardOf(name)`，不能直接 `CARDS[name]`。
- **`var` 提升只提升声明不提升赋值** —— `buildAreas()` 必须在文件末尾的启动段调用，不能放在 `MODE.init()` 里（数据块在它下面）。

⚠ 内容为**公开常识整理，未经实时核实**，只做趣味引导；只写「品类 + 区域」，不虚构具体店名，具体店铺 / 出入口 / 门票以现场或官方信息为准。

想补卡片：往 `CARDS.beijing` / `CARDS.nanjing` 里加一条 `{sights:[...], food:[...], tip:"..."}` 即可，图鉴会自动收进去。

## 贪吃蛇大作战机制对照

| 机制 | 大作战（slither.io 同源） | 本作实现 |
|---|---|---|
| 计分 | 长度即分数，光点越大长得越多 | 同：长度=分数；小豆 +1，掉落大豆 +3 |
| 能否穿过别人身体 | **不能**，撞到就死 | 同：不能穿过（尾随那一两节除外，见机制①） |
| 撞到别人身体 | **死亡** | 双模式：开放世界=掉 3 节肉；大作战=死亡 |
| 死亡/掉肉后 | 尸体散成光点，被别人抢吃快速变长 | 同：掉的肉变大豆子/车站，谁抢到谁长 |
| 加速 | 消耗自身长度换速度 | 同：连点两下/双击方向键冲刺，消耗长度（掉的肉也会被抢） |
| 边界 | 撞墙死亡 | 无墙：64×64 环绕世界，走到头从另一侧出来 |

**两种模式**（开局 toolbar 或底部按钮切换）：
- **开放世界**（默认）：撞到别人身体 → 掉 3 节肉变豆子，不死，继续玩
- **大作战**：撞到别人身体 → 死亡，全身散成豆子被抢，可重新开始（AI 蛇 2.5 秒后自动重生）

## 防眩晕 & 屏幕
- **相机死区**：你在中心 ±2 格内移动时地图完全不动，只有蛇在动；超出才平滑推动相机
- **格间插值渲染**：逻辑 150ms 一步，渲染用 rAF 在两格之间平滑插值，蛇是滑行而非跳格
- **相机 lerp 跟随**：相机以 0.16 系数平滑趋近
- **格子自适应屏幕**：视野恒定约 20×14 格，屏幕越大格子越大、蛇越粗（`CELL` 在 32–90px 之间夹取），手机端不会比原来更小
- **全屏**：画布铺满 `100vw × 100dvh`，**竖屏手机自动转横屏**并铺满，右上角浮层可见排行榜

## 视觉区分（不再误撞）
- **蛇**：连续粗链（深色描边 + 蛇色填充）+ 圆头 + 两只眼睛 + 名字标签；玩家蛇额外有金色外圈
  - 文字版：蛇身每节叠一个字（如「苏」「络」「7」）
  - 地铁版：线路色粗线 + 中间白色虚线（像轨道），头上是线路名（如「1号线」）；**本线的站又大又亮，别线的站小而灰**
- **食物**：
  - 文字版：孤立的圆形发光豆子（朱砂渐变 + 白色描边 + 光晕），中间的字比蛇身字小
  - 地铁版：白色小方块「车站」标记；**本线「下一站」是金色脉冲环 + 「下一站」标签**
- 形状 + 颜色 + 光晕三重区分

## 操作
- **手机**：画面任意位置按住拖动 = 虚拟摇杆；连点两下画面 = 加速冲刺
- **电脑**：方向键 / WASD / 鼠标拖动；连按两次方向键 = 加速冲刺；空格暂停
- 排行榜实时显示每条蛇的长度与排名（超过 10 条只显示前 8 + 你自己）；右下角为世界缩略图（含视野框）

## 托管模式（AI 代打 + 无敌）
点画面左上「托管」按钮：玩家蛇交给 AI（每拍决策、全图视野、不失误），**无敌**（撞到只被挡住，不掉肉不死亡）。动一下方向键 / 摇杆即自动接管回来。

## 难度：刻意轻松（爽点）
核心是「撞到不会死，只掉 3 节肉」。对手被刻意调笨：与玩家同速、迟钝（每 4 拍才决策）、近视（只看得见 12 格内豆子）、7% 失误率、起步更短（5 节 vs 玩家 8 节）、豆子更多（常驻 170 个）。对手撞到别的蛇同样会掉肉，惩罚对等。

## 加一个新版本（不用改引擎）
1. 在 `play.html` 的 `THEMES` 里加一项。文字蛇：
   ```js
   xx: {
     id:"xx", label:"XX", kind:"text",
     title:"XX 贪吃蛇 · 开放世界", foot:"XX · Snaker",
     chars:["X","x"], foodChars:["X","x"],
     playerName:"你·XX", botNames:["小X","阿x","X哥","x妹","XX君","X姐"],
     playerColor:"#1f6f6b",
     botColors:["#c0563a","#7a5cc9","#3a8fc0","#c9a23a","#3ac97a","#c93a8f"],
     intro:"吃<b>发光豆子</b>变长……（照抄其它项的写法）",
     bestKey:"xx_best"
   }
   ```
   地铁线（每条蛇一条线）：把 `kind:"text"` 换成 `kind:"metro"`，用
   `lines:[{name,color,stations:[...]}]` 代替 `chars/botNames/botColors`，其余照抄。
   想要打卡卡就再往 `CARDS` 里补这个城市的站。
2. 在 `index.html` 的 `MENU` 里加一张卡片：`{id:"xx", label:"XX", kind:"text", color:"#1f6f6b", desc:"……"}`。
3. 链接：`play.html?theme=xx`。

> 想做**第三种玩法**（公交线路、诗词链……）不用改引擎：在 `MODES` 里加一个对象，
> 实现同一套钩子（`init/botCount/playerDef/botDef/homeLineFor/mkFood/onTick/onEat/drawFood/drawBody/drawHeadLabel/drawOverlay/updateHud/buildPanel`），
> 再在 `THEMES` 里加一项 `kind:"<新模式>"` 即可。

## 校验
`node smoke-test.js` 用无头 DOM 桩跑五个主题（su / 77 / cc / beijing / nanjing）：初始化、开局、600 帧（含托管）、横屏 resize，断言：
- 无异常、标题正确、开放世界能存活变长
- 蛇数 = 线路数（地铁版每条线一条蛇）
- 横屏位图尺寸 = CSS × dpr（防拉伸）
- 机制①：开局蛇头最近间距 ≥ 4 格；豆子铺满 ≥ 24/64 个分区、单区 ≤ 9
- 机制②：每张精选卡必须有「位置」和「吃食」两类实质内容；区位表覆盖率 ≥ 85%；片区吃食表 ≥ 25 条；重名站不串卡；同一站吃满 3 次出卡、2 次不出卡；没手写卡的站走自动补全；**弹卡后游戏真的暂停、关闭后恢复原状态**；已解锁的站不重复弹卡；有历史数据的站卡片里必须有「历史沿革」段
- 机制④ 换乘玩法：开局线路分配无重复且覆盖全部线路；换乘后线路确实变化且必须是该站经过的线；换乘后原线进度仍被记录；通关目标数 = 全网唯一站数；点亮全网确实触发通关
- 机制③：线路图无 NaN 坐标、节点数 = 全网唯一站数、任意两站最小间距 ≥ 1.5（不重叠）、面板统计自洽、点亮口径正确（吃 1 次不算点亮，吃满 3 次才亮）

游戏内还挂了 `window.__SNAKE__` 只读探针（蛇头、分区豆子数、打卡计数等）供无头自检使用。
