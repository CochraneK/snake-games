## 迭代 14（8b7ee0b → 4eb21ef）：地铁/文字拆成两个「模式模块」（重构）

用户问「地铁和文字线能不能分模块」。给了三个选项，用户选 **单文件内分模块**（保留 play.html 单文件可分享）。

### 做法：MODES 注册表 + 钩子，引擎不再判断模式
- 原状：引擎里 **23 处** `if(THEME.kind==="metro")` 分支，两种模式逻辑缠死。
- 抽出 `MODES = { text:{...}, metro:{...} }`，两个模块各自实现同一套钩子：
  `init / lineBased / botCount / playerDef / botDef / homeLineFor / mkFood / onTick / onEat / drawFood / drawBody / drawHeadLabel / drawOverlay / updateHud / buildPanel`
- 引擎只调 `MODE.xxx()`。**全文件 `THEME.kind` 从 23 处降到 1 处**（第 415 行，仅用于 `MODE=MODES[THEME.kind]` 选模块）。
- 加第三种模式只需：① `MODES` 里加一个对象 ② `THEMES` 里加 `kind`，引擎零改动。

### 收编清单
- 地铁模块：车站池/换乘表/线路色表初始化、`pickStation`、`mkFood`、`ensureNextStation`、`tryBuildHome`、`computeHome`/`updateHome`/`buildHomePanel`、`drawMetroFood`/`drawMetroBody`/`drawMetroHeadLabel`/`drawTransferHint`
- 文字模块：`drawTextFood`（发光豆子）/ `drawTextBody`（粗线 + 每节一字）

### 关键经验（可复用）
1. **抽渲染代码时用 `VW/VH` 代替 `draw()` 里的局部 `S/SH`**（`draw()` 开头就是 `var S=VW, SH=VH`），否则移出去的函数拿不到边界值。

3. 模块内部函数（如 `updateHome`）里的 `THEME.kind!=="metro"` 守卫在收编后是冗余的，一并清掉，模块边界才干净。

## 迭代 15：蛇太小 / 格子尺寸自适应（提交 bb234df）
- 用户反馈"屏幕太小、蛇太小、高度眼距太远看不清"。根因：`resize()` 里 `CELL` 写死 30px → 屏幕越大显示格子越多（全屏 1920 宽 = 64 列），蛇被压成一条细线。
- 改为按屏幕尺寸反推格子：
  `CELL = clamp(Math.min(cssW/VIEW_TARGET_COLS, cssH/VIEW_TARGET_ROWS), CELL_MIN, CELL_MAX)`
  常量 `VIEW_TARGET_COLS=20 / VIEW_TARGET_ROWS=14 / CELL_MIN=32 / CELL_MAX=90`。
- 顺带把 `.stage` 从 `min(97vw,760px)` 放宽到 `min(97vw,920px)`。
- 效果（蛇粗 = 0.8×CELL）：桌面 920 宽 → 37px（+54%）；全屏 1920×1080 → 62px（+158%）；手机端不低于 32px。

### 关键经验（可复用）
1. "屏幕太小"类反馈要先问清是**画布小**还是**元素小**——这次是元素小（CELL 恒定导致视野格数随屏幕线性增长），不是容器小，两者改法完全相反。
2. **`CELL_MIN` 不能低于改动前的 30**：一开始设 28，算下来手机端（窄屏）反而比原来更小，等于负优化。设下限时一定要拿改动前的实际值当基线做对照表。
3. 分辨率无关的自适应公式要同时限制上下界（`clamp`），只给 min 会在超大屏上格子大到只剩几个；只给 max 会退化回老问题。
4. **沙箱 Bash 里 `node -e "…"` 的双引号字符串中的反引号会被 shell 当成命令替换吃掉**（输出为空、stderr 一堆 command not found）。要在文件里写含反引号的内容，改用 Write 落一个临时 .js 再 node 执行。
