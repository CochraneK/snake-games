# 2026-10-09 · snake-games（play.html）

## 迭代 16：两套新机制（提交 fe0c0bb，已推送）

用户要求：① 好好设计反拥挤机制 ② 同一站吃到 N 次弹卡片，讲附近美食/景点。

### 机制① 空间秩序（防拥挤）
四层 + 两个细节：
1. **分区密度网格**：8×8=64 个分区，`dens[]` 每拍 `buildDensity()` 刷新；`crowdAt(x,y)` 取 3×3 分区蛇身节数。
2. **分区豆子配额**：`ZONE_SOFT=3` / `ZONE_HARD=7`；`pickFoodCell` 先挑空区再区内取点（避开蛇嘴 2 格内）。
3. **分散选点**：`pickSpreadCell(occ,heads)` 采样 24 次取「离所有蛇头最远」；开局放蛇也用它。
4. **个人空间斥力**：`steerScore()` 在原有「撞身=-1000 / 目标吸引」之间插入两项——本格与前方 2 格的拥挤惩罚（`CROWD_W=2.6`）、3 格内其他蛇头的排斥（`(9-d2)*1.8`）。botThink/autoThink 合并共用 `steer()`。
5. **尾随豁免** `TAIL_SLACK=1`：允许走进对方最后一节（对方这拍会腾空）。
6. **被围豁免** `SQUEEZE_TICKS=10`：三方向全被占 → 进入 squeeze 状态，期间撞身不掉肉不死。
7. **拥挤预警环**：`crowdAt(head)>CROWD_RING(13)` 时蛇头画脉冲红环。

### 机制② 站点打卡卡
- `CARD_AT=3`：同一站（文字版=同一字）累计吃到第 3 次弹卡，+2 节奖励，每站只弹一次。
- 内容三层：**精选站卡 `CARDS`（北京+南京 101 条）→ 换乘枢纽自动卡（≥3 线）→ 兜底模板卡**（用 lines 数据拼「第 N 站/全线 M 站/起终点」），保证任何站都有内容。
- UI：`#cardLayer` 右上角浮层，不暂停不锁输入，6.5s 自动收起；`#cardGallery` 图鉴 + toolbar「🗂 站卡」按钮 + HUD 计数。
- 内容纪律（用户强调的源透明度）：只写「品类+大致片区」，不虚构店名；卡底固定标注「公开常识整理，未经实时核实」。

### 关键经验（可复用，踩坑记录）
1. **`var` 声明位置会冲掉先前的赋值**：DOM 段先 `cardLayerEl=document.getElementById(...)`，后面模块段又写 `var cardLayerEl=null` → 引用变 null（严格模式下未声明则直接 ReferenceError）。教训：模块段落里要声明就别重复赋初值，或把声明+赋值合并到唯一一处。
2. **「周期性清理」追不上「瞬时洪峰」**：原本每 24 拍做一次豆子再平衡，实测长跑后单区堆到 20 个——蛇撞死一次掉几十颗肉，原地成堆，清理速度差一个量级。改成**插入时硬约束**：所有放豆子走统一入口 `pushFood()`，分区满（`>=ZONE_HARD`）立刻把豆子挪到空区。这是「不变量在写入端」而非「事后修补」。
3. **局部挪动在饱和区无效**：`pickUnderCapCell` 最初只在 ±6 内找候选，整片饱和时挪了还是同区 → 必须加「附近全满 → 全图找空区」的兜底。
4. **分区计数必须精确**：豆子被吃掉时忘了 `zoneFood[z]--`，配额判断会越来越偏（豆子分布看起来均衡，实则计数早已漂移）。现在：吃→减一，批量插入（killSnake/dropMeat/boost）前先 `recountZones()`。
5. **测试断言要选对观测时刻**：「开局蛇头间距 ≥4」只能在 spawn 完立刻测；跑 600 帧后再测，AI 互相靠近是正常行为，会误报。
6. **探针要报「真值」而非维护中的缓存**：`zoneCounts()` 改成按 food 数组现算，一度靠 zoneFood 缓存掩盖了真实的不均衡。
7. `cardLayerEl.children` 在 DOM 桩里不存在 → showCard 抛异常；防御写法 `while(a.children && a.children.length>2)`，顺带给测试桩补 `children/appendChild/removeChild`。
8. 长跑验证值得做：把 smoke-test 的 `drive(sb,300)` 全替换成 2400 帧再跑一遍，才暴露出单区堆豆。做法是临时脚本正则替换帧数 + 追加 soak 断言，跑完删掉。

### 现状数字（2400 帧 soak）
北京 28 线：开局蛇头最近间距 7.2–8.5 格、豆子铺满 62–64/64 分区、单区峰值 4–8。
南京 16 线：间距 10.2–12.0、55–64/64 分区、峰值 3–7。

### 遗留 / 可继续
- 卡片数据仍缺：全网约 600+ 站，只写了 101 条；图鉴里会显示「全网还有 N 站待写卡片」，可作为补数据清单。
- 站序数据仍待抽查（北京昌平/房山/燕房/亦庄T1；南京 5/7/10/S4/S6/S8；南京 6 号线官方 19 站 vs 写的 20 站）。
- 卡片 UI 未做真实浏览器视觉验收（无头桩只验了 DOM 结构），等用户看截图反馈。

## 迭代 17：成就大图（提交 497a5b8，已推送）

用户要「成就大图：总地铁线站点，点亮的是吃掉且读过卡片弹窗的」。

### 实现
- 一张图画全当前城市所有线路所有站：**北京 410 站 / 504 段，南京 266 站 / 291 段**。
- 点亮口径（用户明确要求）：**吃过 + 弹过该站卡片**才算点亮。三态：
  淡灰小点（没去过）/ 白心圈（吃过没读卡）/ 金色实心+光晕（已点亮）；换乘站更大一圈。
- 线路从「本线首个已点亮站 → 末个」那段用线路色点亮（进度像电流沿线路蔓延）。
- 两种视图：**本线高亮**（默认，其余线压淡灰）/ **全网着色**。入口：toolbar「🏆 成就图」、
  图鉴里的「看成就大图」、全屏浮动按钮、`?theme=beijing&map=1` 直达。
- 进度存 `localStorage`（`snake_achieve_<themeId>`，按城市分开），含 hits/cards/charHits/charCards。

### 线路图布局：项目里没有任何坐标数据，靠算法算出来
节点=唯一站名，边=同线相邻站，四股力迭代 320 轮：**硬分离 + 弹簧 + 角度拉直 + 交叉消除**。
固定种子 20261009 → 每次打开同一张图。北京约 30ms。

### 关键经验（可复用，两个大坑）
1. **力导向布局做地铁图会坍缩成毛线球**。两次返工才做对：
   - 纯软斥力（弹簧+1/d² 斥力，无论邻桶还是全量 O(n²)）→ 长距离没有约束，整图向心坍缩 + 几条甩出去的长线；
   - 只加硬分离 → 不糊了，但线路像锯齿互相穿，因为约束只管「不重叠」不管「线能不能穿过别人」。
   - **正解**：硬分离 + 角度拉直（把每条线的折角往直线收）+ 交叉消除（两线段相交时沿中点连线推开，每 10 轮做一次，504 边 × 127k 对）。
2. **迭代顺序有讲究：硬分离必须放在每轮最后**。放在前面时，后面几股力（拉直/消交叉）会重新制造重叠，
   跑完 minSep 仍有 0.45（站点叠在一起）；挪到最后 + 最后 60 轮只做清理，minSep 升到 1.75/2.32。
3. **视觉验收可以用本机 Chrome 无头截图**（`--headless=new --screenshot --window-size --virtual-time-budget`，
   配合 `--user-data-dir` 隔离 profile）。做法：临时脚本复制一份 play.html，注入
   `setTimeout(()=>{S.simulateEat(name,3)…, S.openAchieve()},300)` 造出「已有进度」的状态再截图。
   比在无头 DOM 桩里只看结构有效得多——布局坍缩、毛线球、卡片挡住大图这些问题**只有看图才发现**。
   ⚠ 注意截图页里的 canvas 是真 canvas，能拿到真实渲染结果；而 smoke-test 的桩 ctx 是 Proxy，画不出东西。

### 现状数字
北京：410 站 / 504 段 / 换乘 111 / 最近间距 1.75 / 布局 30ms。
南京：266 站 / 291 段 / 换乘 36 / 最近间距 2.32 / 布局 8ms。

### 遗留
- 卡片数据仍缺：全网 676 站（北京 410 + 南京 266），只写了 101 条精选卡。
- 站序数据仍待抽查（北京昌平/房山/燕房/亦庄T1；南京 5/7/10/S4/S6/S8；南京 6 号线官方 19 站 vs 写的 20 站）。
- 大图暂不支持缩放/平移（410 站挤在一屏，标签有避让但仍偏密）；若要加，考虑拖拽 + 滚轮缩放。

## 迭代 18：站点卡片信息量（提交 74298de，已推送）

用户反馈「每个站的特色卡片介绍，好像不全没信息熵」。先量化，发现比预想严重：
- 全网 676 站（北京 410 + 南京 266）里**只有 103 站有手写卡，573 站（85%）只能显示「第 N 站 / 全线 M 站」**；
- 手写卡里 tip 平均 16.5 字，51 张在讲"换乘"（和自动生成的换乘信息重复）；
- 大量「XX 一带」「XX 商圈」「餐饮密集」这类零信息表述（"燕山一带家常菜"）。

### 改法：四层数据叠加 + 线路数据自动生成
| 层 | 数据 | 覆盖 |
|---|---|---|
| A 区位 | `AREA_SEGS` 按线路区间写「第 A 站到第 B 站属某区」 | 北京 410/410、南京 266/266 = **100%** |
| B 手写精选 | `CARDS[城市][站名]` | 北京 73 / 南京 28 站（升级了最空的 18 条） |
| C 片区吃食 | `FOODZONE`，33 个区域 → 代表性吃食 | 全网 |
| D 地标类别 | 站名关键词自动判（公园/山/寺/高校/机场/城门/水系） | 全网 |
自动补全：站序、邻站、**到终点还剩几站**、可换乘线路。

### 关键经验（可复用）
1. **「按线路区间写地理」比逐站标注省 10 倍维护量**：写法是 `["苹果园","玉泉路","石景山"]`（起止**站名**而非下标），
   运行时 `stations.indexOf` 定位区间；站名对不上就跳过该段（安全降级，不会整张表错位）。
2. **抓出真 bug：两城重名站会串卡**。北京 4 号线也有「新街口」，南京 1/2 号线也有「新街口」——
   `CARDS[name]` 让北京新街口显示出南京的鸭血粉丝汤。修法：数据按城市 id 分组 + `cardOf(name)` 取。
   同类重名：杨庄、奥体中心。**以后做「按站名索引的内容表」必须先查跨主题重名。**
3. **`var` 提升只提升声明不提升赋值**（本项目第三次踩）：`buildAreas()` 放在 `MODE.init()` 里会 undefined，
   因为数据块在文件更下方。规律：**跨模块的初始化调用统一放文件末尾启动段**，别放模块自己的 init 里。
4. **信息量提升会撑破 UI**：卡片从 2 行变 6 行后直接溢出屏幕。必须同时做：限高 `max-height:70vh`、
   整层 `overflow:auto`、底部对齐、z-index 提到 70（否则和页面标题重影）。**改内容密度一定要一起改容器。**
5. **同义去重要做规范化**：`indexOf` 比不了「燕山一带家常菜」vs「燕山一带的家常菜」，
   先剥掉「的/了/多/密集/一带」等修饰词再比（`foodKey()`）。
6. **无手写卡时的兜底文案不能是套话**：原来写「这条线走完全程要留出大半天」，对 6 站的 S9 线是错的。
   改成真数据：「往 XX 方向还有 5 站；本线终点站」。
7. **无头截图的两个坑**（都浪费了几轮）：
   - 截图页是**改动前的旧副本** → CSS 改了没生效。改完必须重新生成截图页再截。
   - `setTimeout` 注入在 `--virtual-time-budget` 下不可靠 → 改**同步注入**（把脚本插在游戏脚本之后）。
   - CSS 入场动画会让截图抓到半透明中间帧（看起来像 z-index 没生效，其实是动画）→ 截图时注入 `.card{animation:none}`。

## 迭代 19：卡片加历史沿革 + 弹卡自动暂停（提交 48bf1b2，已推送）

用户要求两件事：卡片介绍历史；弹卡后暂停方便阅读。

### 历史沿革（新增 E 层`HISTORY`）
- 北京 40+ / 南京 20+ 重点站，写的是「这一站在历史上是什么」：城门方位、皇家园林、铁路门户、
  老城集市、老厂改造⋯⋯
- **刻意不写精确编年年份**（容易错），只写有把握的历史身份。这是内容型数据的通用取舍。
- 卡片里用橙色底 + 红标题单独成段，和「去哪/吃什么」视觉区分。
- 写数据时自己踩了坑：17 处重复键（同一站写两遍）+ 一处误植英文单词（"科举 culture"）→
  写完必须扫一遍重复键。

### 弹卡即暂停
- 理由不只是"方便读"：地铁版节奏只有 150ms 一拍，边跑边读还会被撞。
- 实现：`cardPaused / cardWasPaused` 记住进入前状态 → `paused=true` → `closeCard()` 恢复原状态。
  **恢复原状态而不是强制 false** —— 玩家可能本来就暂停着看成就图，不该被强行开始。
- 底部 `position:sticky` 一条「⏸ 已暂停」+「继续 ▸」，内容再长按钮也可见。
- 去掉 6.5 秒自动关闭（7 段内容根本读不完）。关闭方式：继续按钮 / × / 点卡片空白 / 空格·回车·Esc。
- `togglePause()` 加 `if(cardPaused){ closeCard(); return; }` 分支，否则空格会既关卡片又弹暂停面板。

### 关键经验（可复用）
1. **内容段数增加后必须重算容器限高**：7 段内容在 `max-height:70vh` 下底部「继续」按钮被截断，
   调到 88vh + 层 `overflow:auto` 才解决。**每次加一段内容都要重新截图验容器。**
2. **暂停类需求要问「恢复到什么状态」**：不能无脑设 `paused=false`，要保存进入前的状态再还原。
3. **写多站点数据表必扫重复键**：同一 key 写两遍不会报错（后者覆盖前者），但会掩盖漏写的内容。
4. 测试断言要挑**能真正触发**的输入：我一开始用"已解锁的站再吃一次"测弹卡，结果因为不二次弹卡而误报；
   换成"全新站第一次吃满3 次"才对。**断言失败时先确认前提条件在测试里真的成立。**

## 迭代 20：线路可换乘 + 随机分线 + 全网点亮获胜（提交 84f594f，已推送）

用户要求：「换乘站可以切换成另一条线路，初始时随机分配一条线路，全部小蛇，吃完所有线路（点亮站点卡片）获胜」。

### 玩法改动（地铁版从「各守一线」变成「线路可流转」）
1. **随机分线**：`shuffledAssign(n)` 打乱后发给各蛇，每条线恰好一条蛇，玩家也随机。
2. **换乘**：吃到 ≥2 线车站时弹选择面板 → `applyLine()` 换身份（名字/颜色跟着换）。
   **每条线的进度分别记在 `sn.lineProg[线号]`**，换回来时接着建（这是设计关键——让换乘无代价损失）。
3. **全网点亮获胜**：HUD 加「全网 X / 410」，`netLitCount()` 数 `cardsGot`，满则弹通关。

### 关键经验（可复用）
1. **同名站聚合表 ≠ 线路归属**：`TRANSFER[name]` 是全网同名站聚合，可能包含「该站并不经过」的线路。
   换乘选项必须再查 `lines[li].stations.indexOf(name)>=0`，否则会出现「换到一条这站根本不经过的线」。
2. **同一资源被多个消费者使用时，「唯一性」要显式维护**：手动指定线路时，玩家占的那条线原本有 AI 蛇，
   直接改会破坏「每线一条蛇」→ 做了交换（把原占线者挪到玩家原来的线）。
3. **变量语义要收窄**：`playerLineIdx` 原本混用两种含义（"玩家当前所在线" vs "面板里指定的线"），
   换乘后必然出错。拆成：玩家实际所在线读 `player.lineIdx`，`playerLineIdx` 只表示"手动指定"。
   **教训：加"可变更状态"时，先检查所有引用点是否还成立。**
4. **实体进度跟随身份还是跟随实体**：AI 换乘/重生时进度要保留 → 决定存在蛇上（`sn.lineProg`）而非线上。
5. **z-index 是叠加的**：换乘面板 80 < `.overlay`，被开场遮罩压住。**新加浮层要对照现有所有遮罩的层级。**
6. 测试断言直接抓到一个真 bug：`new Set(assign).size !== lines.length` → 正是手动指定那条路径没被覆盖到。
   **写"分配类"断言时用集合去重计数，比逐项比较更能暴露重复/遗漏。**

   西二旗（清代旗地）、板桥（运盐采石古道）、高庙路（老城南庙宇地名）、三里屯（清代驻屯）⋯⋯

### 关键经验（本次最大的教训，值得反复记）
1. **改嵌套对象字面量，正解是「解析→合并→整体序列化写回」，绝不是「找锚点插字符串」。**
   本次用插字符串的方式连续 8 次把文件改坏：缺逗号、丢`}`、多一层括号、`}}` 少一层 ⋯
   正确做法：`vm.runInNewContext("({" + 切片 + "})")` 解析 → 改对象 → 手写每行序列化 → 整块替换。
   **插字符串只在改扁平/单层结构时才安全。**
2. **改坏多次后立刻 `git checkout -- file` 回滚**，别继续打补丁——越修越乱，且失去了参照基线。
3. **文件是 CRLF，边界匹配必须用 `/\r?\n/` 正则**，用 `indexOf("};\nfunction xxx")` 一定找不到。
4. **「数据要不要写得更具体」是个取舍**，不是越多越好。我给历史写了纪律并写进代码注释：
   ① 只写有把握的（地名由来最可靠；有名胜/机构的次之）② 不写编年式精确年份、不做未核实轶闻。
   宁可少说一句，也不写错——因为错了会直接损害它本来的目的（可信的趣味引导）。
5. 测试加了一条「历史条数 ≥ 60」的断言：防止历史退化成点缀，确保它是内容主体。

## 迭代 22：换乘选择 = 暂停 + 5 秒倒计时（提交 1b0a330，已推送）

用户要求「换线路给 5s 时间选择，且蛇也暂停」。

### 实现要点
- `TRANSFER_MS=5000`，面板顶部显示剩余秒数（1 位小数）+ 橙色进度条（`#trCount` / `#trBarIn`）。
- 弹面板即暂停（`transferPaused=true, paused=true`），关闭时**恢复到进入面板前的暂停状态**
  （`transferWasPaused`），不会把「本来就在暂停看大图」的玩家强行开始。
- **倒计时在 `frame()` 里用 dt 递减，不用 `setInterval`** —— 后者在无头截图的
  `--virtual-time-budget` 下会漂移（截图时 6.5s 自动关的卡片就因此抓不到）。
- 超时 / 按 Esc / 点「不换」→ 一律默认**不换**，游戏自动恢复。
- Esc 优先级高于空格：两个暂停态可能共存（换乘面板 + 卡片），先关换乘面板。

### 关键经验
1. **「限时 + 暂停」是决策类 UI 的标准解**：限时解决"不能干等"，暂停解决"操作会挨撞"。
   单用任一个都不够 —— 只限时会在倒计时里被撞；只暂停会让节奏断掉。
2. **游戏内倒计时不要用 setInterval**，跟 rAF 里的 `dt` 一起算：天然与帧同步、
   页面失焦时不跑、测试可注入（探针 `tickTransfer(ms)`）。
3. **截图本身就是超时测试**：拍「剩余 0.1s」那一张时，面板已经消失 = 自动收起逻辑正确。
