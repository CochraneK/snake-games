# 2026-10-09 · snake-games（play.html）

## 迭代 16：两套新机制（提交 fe0c0bb，已推送）

用户要求：① 好好设计反拥挤机制 ② 同一站吃到 N 次弹卡片，讲附近美食/景点。

### 机制① 空间秩序（防拥挤）
四层 + 两个细节：
1. **分区密度网格**：8×8=64 个分区，`dens[]` 每拍 `buildDensity()` 刷新；`crowdAt(x,y)` 取 3×3 分区蛇身节数。
2. **分区豆子配额**：`ZONE_SOFT=3` / `ZONE_HARD=7`；`pickFoodCell` 先挑空区再区内取点（避开蛇嘴 2 格内）。
3. **分散选点**：`pickSpreadCell(occ,heads)` 采样 24 次取「离所有蛇头最远」；开局放蛇也用它。
4. **个人空间斥力**：`steerScore()` 在原有「撞身=-1000 / 目标吸引」之间插入两项——本格与前方 2 格的拥挤惩罚（`CROWD_W=2.6`）、3 格内其他蛇头的排斥（`(9-d2)*1.8`）。botThink/autoThink 合并共用 `steer()`。
5. **尾随豁免** `TAIL_SLACK=1`：允许走进对方最后一节（对方这拍会腾空）。
6. **被围豁免** `SQUEEZE_TICKS=10`：三方向全被占 → 进入 squeeze 状态，期间撞身不掉肉不死。
7. **拥挤预警环**：`crowdAt(head)>CROWD_RING(13)` 时蛇头画脉冲红环。

### 机制② 站点打卡卡
- `CARD_AT=3`：同一站（文字版=同一字）累计吃到第 3 次弹卡，+2 节奖励，每站只弹一次。
- 内容三层：**精选站卡 `CARDS`（北京+南京 101 条）→ 换乘枢纽自动卡（≥3 线）→ 兜底模板卡**（用 lines 数据拼「第 N 站/全线 M 站/起终点」），保证任何站都有内容。
- UI：`#cardLayer` 右上角浮层，不暂停不锁输入，6.5s 自动收起；`#cardGallery` 图鉴 + toolbar「🗂 站卡」按钮 + HUD 计数。
- 内容纪律（用户强调的源透明度）：只写「品类+大致片区」，不虚构店名；卡底固定标注「公开常识整理，未经实时核实」。

### 关键经验（可复用，踩坑记录）
1. **`var` 声明位置会冲掉先前的赋值**：DOM 段先 `cardLayerEl=document.getElementById(...)`，后面模块段又写 `var cardLayerEl=null` → 引用变 null（严格模式下未声明则直接 ReferenceError）。教训：模块段落里要声明就别重复赋初值，或把声明+赋值合并到唯一一处。
2. **「周期性清理」追不上「瞬时洪峰」**：原本每 24 拍做一次豆子再平衡，实测长跑后单区堆到 20 个——蛇撞死一次掉几十颗肉，原地成堆，清理速度差一个量级。改成**插入时硬约束**：所有放豆子走统一入口 `pushFood()`，分区满（`>=ZONE_HARD`）立刻把豆子挪到空区。这是「不变量在写入端」而非「事后修补」。
3. **局部挪动在饱和区无效**：`pickUnderCapCell` 最初只在 ±6 内找候选，整片饱和时挪了还是同区 → 必须加「附近全满 → 全图找空区」的兜底。
4. **分区计数必须精确**：豆子被吃掉时忘了 `zoneFood[z]--`，配额判断会越来越偏（豆子分布看起来均衡，实则计数早已漂移）。现在：吃→减一，批量插入（killSnake/dropMeat/boost）前先 `recountZones()`。
5. **测试断言要选对观测时刻**：「开局蛇头间距 ≥4」只能在 spawn 完立刻测；跑 600 帧后再测，AI 互相靠近是正常行为，会误报。
6. **探针要报「真值」而非维护中的缓存**：`zoneCounts()` 改成按 food 数组现算，一度靠 zoneFood 缓存掩盖了真实的不均衡。
7. `cardLayerEl.children` 在 DOM 桩里不存在 → showCard 抛异常；防御写法 `while(a.children && a.children.length>2)`，顺带给测试桩补 `children/appendChild/removeChild`。
8. 长跑验证值得做：把 smoke-test 的 `drive(sb,300)` 全替换成 2400 帧再跑一遍，才暴露出单区堆豆。做法是临时脚本正则替换帧数 + 追加 soak 断言，跑完删掉。

南京 16 线：间距 10.2–12.0、55–64/64 分区、峰值 3–7。

### 遗留 / 可继续
- 卡片数据仍缺：全网约 600+ 站，只写了 101 条；图鉴里会显示「全网还有 N 站待写卡片」，可作为补数据清单。

## 迭代 17：成就大图（提交 497a5b8，已推送）

用户要「成就大图：总地铁线站点，点亮的是吃掉且读过卡片弹窗的」。

### 实现
- 一张图画全当前城市所有线路所有站：**北京 410 站 / 504 段，南京 266 站 / 291 段**。
- 点亮口径（用户明确要求）：**吃过 + 弹过该站卡片**才算点亮。三态：
  淡灰小点（没去过）/ 白心圈（吃过没读卡）/ 金色实心+光晕（已点亮）；换乘站更大一圈。
- 线路从「本线首个已点亮站 → 末个」那段用线路色点亮（进度像电流沿线路蔓延）。
- 两种视图：**本线高亮**（默认，其余线压淡灰）/ **全网着色**。入口：toolbar「🏆 成就图」、
  图鉴里的「看成就大图」、全屏浮动按钮、`?theme=beijing&map=1` 直达。
- 进度存 `localStorage`（`snake_achieve_<themeId>`，按城市分开），含 hits/cards/charHits/charCards。

### 线路图布局：项目里没有任何坐标数据，靠算法算出来
节点=唯一站名，边=同线相邻站，四股力迭代 320 轮：**硬分离 + 弹簧 + 角度拉直 + 交叉消除**。
固定种子 20261009 → 每次打开同一张图。北京约 30ms。

### 关键经验（可复用，两个大坑）
1. **力导向布局做地铁图会坍缩成毛线球**。两次返工才做对：
   - 纯软斥力（弹簧+1/d² 斥力，无论邻桶还是全量 O(n²)）→ 长距离没有约束，整图向心坍缩 + 几条甩出去的长线；
   - 只加硬分离 → 不糊了，但线路像锯齿互相穿，因为约束只管「不重叠」不管「线能不能穿过别人」。
   - **正解**：硬分离 + 角度拉直（把每条线的折角往直线收）+ 交叉消除（两线段相交时沿中点连线推开，每 10 轮做一次，504 边 × 127k 对）。
2. **迭代顺序有讲究：硬分离必须放在每轮最后**。放在前面时，后面几股力（拉直/消交叉）会重新制造重叠，
   跑完 minSep 仍有 0.45（站点叠在一起）；挪到最后 + 最后 60 轮只做清理，minSep 升到 1.75/2.32。
3. **视觉验收可以用本机 Chrome 无头截图**（`--headless=new --screenshot --window-size --virtual-time-budget`，
   配合 `--user-data-dir` 隔离 profile）。做法：临时脚本复制一份 play.html，注入
   `setTimeout(()=>{S.simulateEat(name,3)…, S.openAchieve()},300)` 造出「已有进度」的状态再截图。
   比在无头 DOM 桩里只看结构有效得多——布局坍缩、毛线球、卡片挡住大图这些问题**只有看图才发现**。
   ⚠ 注意截图页里的 canvas 是真 canvas，能拿到真实渲染结果；而 smoke-test 的桩 ctx 是 Proxy，画不出东西。
