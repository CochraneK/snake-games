- 实现要点：
  - **双模式**（尊重用户先前"不撞死"硬要求，未擅自推翻）：`mode=open` 默认，撞身掉 3 节肉变大豆子；`mode=battle` 撞身即死、全身散成豆子、AI 蛇 2.5s 重生。

  - **视觉区分**：蛇=连续粗链(深色描边+蛇色+圆头+两眼+名字，玩家加金圈)；食物=孤立圆形发光豆(朱砂渐变+白描边+光晕，字比蛇身小)。形状/颜色/光晕三重区分，解决"把蛇身误当食物"。
  - **屏幕**：视野按 `clientWidth/26` clamp[15,30] 自适应；stage `min(97vw,760px)`；新增全屏按钮（body.fs 隐藏全部 UI，画布 100vmin）。

## 迭代 6（fcb8241 → 3971c75）
- 用户反馈：① 横屏全屏后**食物文字往右歪**；② 全屏要**看得见排行榜**。
- ① 根因（重要，通用坑）：**canvas 位图尺寸 ≠ CSS 盒子尺寸时会被非等比拉伸**，圆豆变椭圆、文字歪斜。
  - 触发场景：进全屏后 `resize()` 放在 `setTimeout(350)` 里 → 这 350ms 内 CSS 已变、位图没变 = 拉伸；横竖屏切换时读到的 `clientHeight` 也可能是旧值。
  - 修法：a) `setFs` 里**立即** `resize()`，再 350/900ms 各兜一次；b) `resize()` 中先清内联 height 再**回读** `clientWidth/clientHeight`（触发回流）后才设 `canvas.width/height`；c) `100vh`→`100dvh`（移动端工具栏）；d) 加 `ResizeObserver`（尺寸真变了才重算，用 lastCW/lastCH 比对）+ `visualViewport.resize` 监听。
  - 断言式验收：冒烟测试直接比对 `canvas.width/height` 与 `cssW*dpr/cssH*dpr`——横屏 1600×800 且宽高比 2.000 == CSS 2.000。**这类"渲染变形"问题用位图尺寸断言能抓到，肉眼/语法检查抓不到。**
- ② 全屏排行榜：从 `body.fs{display:none}` 列表里**移除 `.board`**，改成 `position:fixed; right/top:8px; flex-direction:column; pointer-events:none` 的右上角浮层（不挡摇杆）。

- **全屏强制横屏**（用户："全屏我希望是横屏的，现在还是竖屏"）：
  - 优先 `screen.orientation.lock('landscape')`（Android Chrome 需先进入全屏才生效，故延迟 150ms 调用；用 Promise 成功后置 `orientLocked=true`）。
  - iOS 等不支持 → **CSS 兜底**：`body.fs-rot .stage{position:fixed;top:50%;left:50%;width:100dvh;height:100dvw;transform:translate(-50%,-50%) rotate(90deg);}`，并把全屏/托管浮动按钮改 `position:fixed` 以免跟着转。
  - **关键坑**：画面被 rotate(90deg) 后，触摸→画面坐标要**逆旋转换算**，否则摇杆方向偏 90°。
    公式：设 stage 外接框中心偏移 (ox,oy)，则局部偏移 = (oy, -ox)，再回到局部中心。封装成 `toLocal(cx,cy)`，touchstart/move、mousedown/mousemove 统一走它。
  - `updateOrientation()` 按 `innerHeight>innerWidth && fsMode && !orientLocked` 决定要不要转；真实转成横屏后自动撤掉。
- 验收：冒烟测试断言 `body.fs-rot` 在竖屏全屏时为 true、退出后为 false，并在旋转态下跑摇杆无异常。
